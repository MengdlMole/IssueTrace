# IssueTrace 1.0.0 架构

IssueTrace 是单用户、本地优先桌面应用。程序包与用户工作区严格分离；运行时不需要账号、网络、数据库服务或云 API。

## 技术结构

```text
Main.qml（窗口与管理/记录/日历页导航）
├── IssueInbox（可拖动分组树、事件标签筛选、组合检索与排序）
├── IssueEditorList（可调高度的关注/全部事件、全文检索与排序）
├── IssueCalendar（按提出日期的月视图与单日事件列表）
├── EventMetadataFields（快速创建与详情共用的历史选择字段）
├── TimelineComposer（快速记录、草稿、附件）
├── TimelineList（虚拟化时间线）
└── IssueDetailsDialog（补充信息、本地草稿与显式保存）
            ↓
App 单例 / AppController（UI 命令、投影、提醒与工作区编排）
            ↓
IssueExportService ── Markdown / XLSX 只读导出
            ↓
C++20 核心与存储 ── SQLite/FTS5 + 附件文件库
```

Qt 只负责跨平台桌面壳、QML、剪贴板、拖放、文件对话框、托盘和通知。`App` 通过 QML 单例注册，组件不依赖隐式上下文变量。`AppController` 保留兼容的 UI 接口，Markdown/XLSX 生成由独立应用服务承担；业务数据、迁移、搜索、备份和离线升级仍位于 C++ 层。

## 界面与状态

主窗口使用 `StackLayout` 分离事件管理页、事件记录页和事件日历页，顶栏页签完全由 `currentPage` 派生选中状态。管理页用 `SplitView` 在左侧构造多级分组投影、右侧展示所选分组及其后代的事件。记录页使用独立的横向 `SplitView`，左侧内部再用纵向 `SplitView` 调整“需要关注/全部事件”高度；记录页列表不继承管理页筛选，避免编辑时事件意外消失。右侧保持计时、状态、固定输入区和虚拟化时间线。日历使用未受管理筛选影响的完整事件投影，默认按 `reported_at` 聚合，也可用 `created_at` 到 `resolved_at` 的闭区间作为每日投影；未完成事件的终点是当天。点击日历事件复用记录页选择逻辑。时间线输入按事件自动保存草稿；时间线变更会重新读取当前事件投影，使进展即时同步到详情。事件详情只在点击“保存”时提交，已编辑的详情草稿不会被后端投影刷新覆盖。事件和时间线的删除由 QML 统一二次确认，存储层执行软删除。

五个时间概念必须分开：

- `created_at`：问题总年龄起点；
- `status_changed_at`：当前状态停留起点；
- `updated_at`：最近业务活动，用于未推进判断。
- `tracked_milliseconds`：已经暂停并结算的累计投入时间；
- `timer_started_at`：当前运行段的起点，可空，重启后继续计时。
- 累计时间修正使用独立写入接口，只允许 `timer_started_at` 为空时执行，且不更新 `updated_at`，避免修正计时改变事件的业务排序。

只设置提醒不会修改 `updated_at`。提醒时间保存在 `remind_at`，进程内去重桌面通知；到期状态本身持久化，所以重启后仍会提醒。

## 数据与事务

SQLite 是唯一事实来源，数据库存 UTC 毫秒，UI 按本地时区显示。全文索引包含问题字段、有效时间线、总结和附件原名。

创建/编辑/软删除及搜索索引刷新在事务内完成。分组拖放将源路径及全部后代作为一个事务批量迁移，顺序写入工作区元数据。带附件的新记录先读取和校验全部文件，再创建记录和复制文件；失败时回滚或软删除刚创建的记录。永久删除会先把附件重命名到同文件系统的临时区，数据库事务成功后再移除；事务失败则恢复原路径。数据库启用 `secure_delete`，只保存工作区相对路径，并拒绝路径逃逸和符号链接。

## 导出、备份与升级

Markdown/XLSX 是只读投影，不反向同步。Markdown 先在隐藏临时目录生成完整结果，再把附件和 Markdown 逐个发布到最终目录，以兼容 Obsidian 等工具的文件监听；失败时清理临时目录和不完整目标，目标已存在则直接失败。SQLite 在线备份与附件副本组成完整备份，恢复前再生成安全快照。

发布物是完整便携压缩包。独立升级器验证版本、平台、架构、路径和每个文件的 SHA-256，然后在同文件系统暂存并切换程序目录；健康检查失败回滚。升级器不修改外部工作区。
