# IssueTrace 发布检查清单

## 发布等级

- **开发包**：文件名带 `-dev`，可用于开发者或受控内部测试，不承诺操作系统信任提示、兼容性或无障碍验收。
- **候选版**：三个目标系统均由原生流水线构建并通过自动测试，但仍在进行人工验收。
- **稳定版**：下列所有项目都有可追溯证据，文件名才可以移除 `-dev`。

## 稳定发布硬门槛

### 产品与身份

- [ ] 确认产品名称、域名、代码托管组织和应用标识符可以合法、长期使用；
- [ ] 确定唯一发布渠道和维护者身份；
- [ ] 为 Windows 与 macOS 使用稳定、可验证的发布者身份。

### 原生构建与系统验收

- [ ] Windows 11 x86_64 原生构建；验证首次启动、中文/长路径、剪贴板图片、拖放附件、托盘通知、XLSX/Markdown 导出和升级回滚；
- [ ] macOS 13+ arm64 原生构建；完成 Developer ID 签名、公证、Gatekeeper、通知、剪贴板、文件权限和升级回滚验证；
- [ ] Linux x86_64 在选定的保守 glibc 基线上构建；分别验证 Ubuntu 22.04/24.04 的 X11 与 Wayland；
- [ ] 至少执行一次从上一候选版本升级，并验证失败回滚和工作区数据不变；
- [ ] 使用至少 1,000 条时间线和多种大附件做性能、磁盘空间不足与异常退出测试；
- [ ] 完成键盘操作、缩放、高对比度和屏幕阅读器基础验收。

### 安全与数据

- [ ] 发布归档只包含清单声明的文件，拒绝绝对路径、路径穿越、重复路径和越界符号链接；
- [ ] 对归档炸弹、磁盘空间不足、被篡改清单和超大文件做负向测试；
- [ ] 外部发布页提供独立 SHA-256；应用内完整性检查不得描述成发布者身份验证；
- [ ] 完成全新工作区、备份、恢复、schema 升级和未来版本拒绝测试；
- [ ] 明确崩溃后的日志位置和用户可执行的恢复步骤。

### 许可与供应链

- [ ] 源码进入版本控制，发布 commit 不含未提交改动，并创建不可变版本 tag；
- [ ] 发布二进制包、对应源码包及各自 SHA-256；
- [ ] `LICENSE`、`THIRD_PARTY_NOTICES.md`、平台依赖锁和 CycloneDX SBOM 与最终载荷一致；
- [ ] Qt、libxlsxwriter、zlib、SQLite 和编译器运行库的版本、许可与公开源码地址可追溯；
- [ ] 对最终压缩包运行恶意软件扫描，并保存构建日志、测试日志和校验和。

公开网络已有使用 “IssueTrace” 名称的问题跟踪服务；在确认命名、商标和域名策略前，不应使用该名称公开发布。当前 `io.issuetrace.desktop.dev` 也只是开发包占位符，稳定构建必须改为发布者实际控制的标识符。

因此 0.4.0 可以交付给了解限制的内部测试者，不能标记为面向公众的稳定版本。
