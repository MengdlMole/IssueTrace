# IssueTrace 0.5 产品边界

## 目标

IssueTrace 帮助程序员在被外部问题打断时，立即捕获问题，随后以最低整理成本留下可追溯的排查过程，并在问题停滞时提醒继续处理。

成功标准不是“信息最完整”，而是：新问题 10 秒内建档；任何进展 5 秒内追加；用户一眼看出哪些问题正在等待、停留多久和多久没有推进；完成后无需重新搬运即可导出总结素材。

## 唯一主流程

```text
收到问题 → 快速创建 → 追加任意记录/证据 → 状态或提醒控制 → 完成 → 导出
```

界面分为三个紧凑页面：事件管理页以左侧多级分组树、右侧事件结果负责筛选与定位；点击事件进入记录页。记录页以左侧“需要关注/全部事件”列表、右侧编辑区负责事件间快速切换、计时、状态和时间线，两个列表区域可调整高度。事件日历按提出日期提供月视图和单日列表，用于回顾每天收到的事件。快速创建始终位于顶栏，详情、提醒和低频工具使用弹窗或菜单。

## 功能规则

- 创建只要求事件正文并自动填写时间；优先级、分组、标签、提出人、处理人、版本号和服务均可在快速创建时选填。
- 分组、提出人、处理人、版本号和服务提供历史值下拉框，同时允许录入新值；快速创建和详情编辑复用同一组字段组件。
- 详情编辑使用弹窗内草稿，历史值选择和手动输入都只更新草稿；点击“保存”才一次性写入，“取消”不修改已存数据。
- 状态固定为 `pending`、`investigating`、`waiting`、`completed`。
- 时间线固定为普通记录、进展、结论；支持文字、截图和附件，自动记录时间并倒序展示。
- 最新有效进展投影为列表摘要；记录编辑后立即更新搜索和未活动时间。
- 待处理停留 30 分钟，或处理中 60 分钟没有活动，进入“需要关注”。等待状态只在显式提醒到期时关注，避免无意义催促。
- 显式提醒提供 30 分钟、2 小时、明天此时快捷项，也可输入任意未来本地时间；提醒到期发桌面通知并保留关注状态，直到取消、改期或完成。
- 管理页按 `/` 分隔的多级分组路径展示，空分组统一归入“默认分组”。分组拖到目标行上方或下方可持久化同级排序，拖到中部可连同全部后代移动到另一分组下。
- 管理页使用覆盖标题、描述、进展、标签、服务、版本和问题单的全文搜索，并可组合状态、优先级、服务、版本、问题单、标签及累计处理时长筛选。全文搜索、状态和优先级常驻，低频条件折叠；所有生效条件统一显示为可移除摘要并支持一键重置。标签支持从事件卡片直接多选；排序支持最后修改、创建时间、优先级、名称和累计处理时间。页面主列表统一命名为“事件”。
- 事件累计处理时间可在计时暂停后按小时、分钟修正；运行中的计时禁止直接覆盖，避免丢失当前计时段；再次开始计时后从修正值继续累计。
- 记录页列表默认按最后修改时间倒序；可按创建时间或优先级排序，并按优先级筛选。标题、描述、进展和标签共用一个搜索框；到期提醒、待处理超时和处理中久未更新的事件独立置顶。
- 开始/暂停计时只累计投入时长，不把计时心跳误算成事件更新；完成事件会自动暂停计时。
- Markdown 是单向、自包含导出；XLSX 是当前筛选结果导出。
- 总结模板依次提供事件概述、事件处理、事件解决、验证和遗留问题、后续建议及相关附件；不自动复制整条时间线。

## 不做

0.4 不做团队协作、云表单同步、XLSX 导入映射、双向 Markdown 同步、任意自定义字段/状态、复杂统计大盘、内置 AI/OCR、日志解析和联网更新。这些需求只有在不增加日常操作成本且有稳定真实场景后才重新评估。

## 验收

1. 创建、选择、编辑状态和连续追加记录不离开主页面。
2. 输入草稿在切换问题、关闭窗口和重启后恢复。
3. 长时间线可滚动并使用虚拟化列表，不随记录数线性创建全部 UI 对象。
4. 图片和附件与所属记录同时保存，失败不留下半条记录。
5. 状态停留、未活动和提醒使用持久化时间，重启后不重置。
6. 旧 schema 自动备份后迁移，旧状态映射到四状态模型。
7. Markdown 导出中的图片与附件链接可以离线打开。
8. Debug、Release、更新器、滚动烟测和便携包烟测全部通过。
