# IssueTrace 0.4 产品边界

## 目标

IssueTrace 帮助程序员在被外部问题打断时，立即捕获问题，随后以最低整理成本留下可追溯的排查过程，并在问题停滞时提醒继续处理。

成功标准不是“信息最完整”，而是：新问题 10 秒内建档；任何进展 5 秒内追加；用户一眼看出哪些问题正在等待、停留多久和多久没有推进；完成后无需重新搬运即可导出总结素材。

## 唯一主流程

```text
收到问题 → 快速创建 → 追加任意记录/证据 → 状态或提醒控制 → 完成 → 导出
```

界面只有一个工作页面：左侧问题收件箱，右侧当前问题时间线。详情、提醒和低频工具使用弹窗或菜单，不引入大盘、管理、工作台、总结编辑器、模板设置等独立页面。

## 功能规则

- 创建只要求问题正文，自动填写时间；提出人可选。
- 状态固定为 `pending`、`investigating`、`waiting`、`completed`。
- 时间线固定为普通记录、进展、结论；支持文字、截图和附件，自动记录时间并倒序展示。
- 最新有效进展投影为列表摘要；记录编辑后立即更新搜索和未活动时间。
- 待处理停留 30 分钟，或处理中 60 分钟没有活动，进入“需要关注”。等待状态只在显式提醒到期时关注，避免无意义催促。
- 显式提醒提供 30 分钟、2 小时、明天此时快捷项，也可输入任意未来本地时间；提醒到期发桌面通知并保留关注状态，直到取消、改期或完成。
- 搜索覆盖问题字段、时间线、总结和附件名；状态可以筛选。
- Markdown 是单向、自包含导出；XLSX 是当前筛选结果导出。

## 不做

0.4 不做团队协作、云表单同步、XLSX 导入映射、双向 Markdown 同步、任意自定义字段/状态、复杂统计大盘、内置 AI/OCR、日志解析和联网更新。这些需求只有在不增加日常操作成本且有稳定真实场景后才重新评估。

## 验收

1. 创建、选择、编辑状态和连续追加记录不离开主页面。
2. 输入草稿在切换问题、关闭窗口和重启后恢复。
3. 长时间线可滚动并使用虚拟化列表，不随记录数线性创建全部 UI 对象。
4. 图片和附件与所属记录同时保存，失败不留下半条记录。
5. 状态停留、未活动和提醒使用持久化时间，重启后不重置。
6. 旧 schema 自动备份后迁移，旧状态映射到四状态模型。
7. Markdown 导出中的图片与附件链接可以离线打开。
8. Debug、Release、更新器、滚动烟测和便携包烟测全部通过。
