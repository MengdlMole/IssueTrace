# 便携压缩包

IssueTrace 只分发完整、解压即用的压缩包，不提供安装器、自解压程序或在线更新服务。

## 发布物

- `IssueTrace-<version>-windows-x86_64.zip`
- `IssueTrace-<version>-macos-<arch>.zip`（稳定发布）
- `IssueTrace-<version>-linux-x86_64.tar.gz`

同一份完整压缩包既用于首次使用，也作为离线升级输入。每个包必须包含应用、运行库、`release-manifest.json`、许可证、第三方声明、依赖清单和便携使用说明。

未经目标系统原生验收或未完成平台签名的候选包必须带 `-dev`，不得作为稳定发布物上传。

## 首次使用

1. 校验发布渠道提供的 SHA-256；
2. 完整解压到任意可写目录；
3. 直接运行平台入口；
4. 在程序中创建或选择位于程序包之外的工作区。

不能只复制主可执行文件，也不能直接在压缩软件预览窗口中运行。

## 使用压缩包升级

始终可用的安全方式：退出 IssueTrace，把新版完整解压到一个新目录，启动新版并选择原工作区；确认正常后再删除旧程序目录。

应用内提供“从新版压缩包升级”：选择新版完整压缩包后，主程序先验证并备份工作区，独立升级帮助程序校验归档路径、平台、架构、版本及逐文件 SHA-256，解压到同文件系统暂存目录，退出主程序，切换程序载荷并保留一个可回滚版本。新版未写入健康标记时自动恢复旧版。

不要直接覆盖旧程序目录。直接覆盖可能遗留新版本已经删除的运行库文件。

## 发布检查

1. 在目标系统原生构建并运行测试；
2. 只收集应用真实需要的运行库和 QML 模块；
3. 生成并验证 `release-manifest.json`；
4. 创建版本化压缩包；
5. 在全新目录完成首次启动验收；
6. 用上一版本完成压缩包升级和回滚验收；
7. 生成 SHA-256、SBOM 和完整第三方许可包；
8. 发布后不得覆盖同版本压缩包。

详细安全边界见 `docs/adr/0006-portable-archives-and-offline-upgrades.md`。
